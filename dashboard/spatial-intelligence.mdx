# Spatial Intelligence

Upview's Spatial Intelligence system tracks where your players go, what they feel, and what they do — then visualizes it all on an interactive heatmap dashboard. Zero code required.

<Info>
  Spatial Intelligence is included on all Upview plans. No additional setup beyond the standard SDK is required.
</Info>

## Features at a Glance

| Feature | Description |
|---------|-------------|
| **Density Heatmaps** | See where players cluster, with adjustable radius, intensity, and opacity |
| **Emotion Tracking** | Color-coded dots show player emotions (happy, frustrated, excited, etc.) |
| **Event Markers** | Track deaths, purchases, interactions, and achievements as map icons |
| **Zone Analytics** | See time spent and player counts per named zone |
| **Path Trails** | Visualize individual player movement paths |
| **Time Scrubber** | Replay your data over time with a slider control |
| **Blueprint Overlays** | Upload a top-down map image for spatial context |
| **Live Mode** | Auto-refresh every 5 seconds for real-time monitoring |
| **Export** | Download your data as PNG, JSON, or CSV |

## Quick Start (Zero Code)

The entire heatmap system works with **zero Lua code**. Just tag parts in Roblox Studio:

### Step 1: Enable Heatmaps in Your SDK Config

```lua
local Upview = require(game.ServerScriptService.Upview)

Upview:Init({
    ApiKey = "your-api-key",
    EnableHeatmaps = true,   -- This is all you need
}):Start()
```

### Step 2: Tag Anchor Parts (Optional)

For object-space tracking (e.g., houses, rooms, vehicles), tag any `BasePart` in Roblox Studio:

1. Select the floor or root part of your structure
2. In the **Tags** editor, add the tag: `UpviewAnchor`
3. In **Properties → Attributes**, add: `UpviewContext` = `"My_House_Layout"` (string)

<Tip>
  When players are near an anchor, their coordinates are automatically converted to **object-space** relative to that part. This means identical house layouts will produce identical heatmaps, even if they're placed in different world locations.
</Tip>

### Step 3: Tag Zone Parts (Optional)

To track which zone players are in, tag any `BasePart` that represents a zone boundary:

1. Select a part that covers your zone area (e.g., a transparent block over your lobby)
2. Add the tag: `UpviewZone`
3. Add attribute: `UpviewZoneName` = `"Lobby"` (string)

That's it. The SDK automatically detects when players enter/exit zones and includes zone data in every position sample.

## Emotion Tracking

Track how players feel at every location. Emotions are color-coded on the dashboard:

| Emotion | Color | Dot |
|---------|-------|-----|
| Happy | Green | 🟢 |
| Frustrated | Red | 🔴 |
| Excited | Yellow | 🟡 |
| Calm | Blue | 🔵 |
| Confused | Purple | 🟣 |
| Bored | Orange | 🟠 |
| Neutral | Gray | ⚪ |

### Setting Emotions via Code

```lua
local Heatmap = Upview:GetService("Heatmap")

-- Set a player's emotion (persists until changed or cleared)
Heatmap:SetPlayerEmotion(player, "frustrated")

-- Clear emotion
Heatmap:ClearPlayerEmotion(player)

-- Get current emotion
local emotion = Heatmap:GetPlayerEmotion(player) -- "frustrated" or nil
```

### Auto-Detection Examples

You can wire emotions to game events:

```lua
-- Player dies → frustrated
player.Character.Humanoid.Died:Connect(function()
    Heatmap:SetPlayerEmotion(player, "frustrated")
    -- Auto-clear after respawn
    task.delay(5, function()
        Heatmap:ClearPlayerEmotion(player)
    end)
end)

-- Player makes a purchase → excited
MarketplaceService.PromptGamePassPurchaseFinished:Connect(function(plr, id, purchased)
    if purchased then
        Heatmap:SetPlayerEmotion(plr, "excited")
    end
end)
```

## Event Markers

Record one-time spatial events that render as special icons on the dashboard:

```lua
local Heatmap = Upview:GetService("Heatmap")

-- Record a death event
Heatmap:RecordEvent(player, "death", { cause = "fall", zone = "BossRoom" })

-- Record a purchase
Heatmap:RecordEvent(player, "purchase", { item = "Sword", price = 100 })

-- Record a custom interaction
Heatmap:RecordEvent(player, "interaction", { target = "NPC_Shopkeeper" })

-- Record an achievement
Heatmap:RecordEvent(player, "achievement", { name = "First Kill" })
```

Event markers appear as colored diamonds on the heatmap, making it easy to see where critical game moments happen.

## Advanced Configuration

All heatmap parameters can be customized in your `Upview:Init()` config:

```lua
Upview:Init({
    ApiKey = "your-api-key",
    EnableHeatmaps = true,

    -- Tracking
    HeatmapTrackingInterval = 2,       -- Seconds between position samples (default: 2)
    HeatmapMinDistance = 0.5,          -- Min studs moved before recording (default: 0.5)
    HeatmapMaxPointsPerFlush = 50,     -- Buffer size before auto-flush (default: 50)

    -- Auto-Anchoring
    HeatmapAutoAnchorEnabled = true,   -- Use CollectionService tags (default: true)
    HeatmapAutoAnchorTag = "UpviewAnchor",  -- Tag name (default: "UpviewAnchor")
    HeatmapAutoAnchorDistance = 200,   -- Max studs from anchor (default: 200)

    -- Auto-Zones
    HeatmapAutoZoneEnabled = true,     -- Use zone detection (default: true)
    HeatmapAutoZoneTag = "UpviewZone", -- Tag name (default: "UpviewZone")
}):Start()
```

## Manual Anchoring (Power Users)

If you prefer full manual control over anchoring instead of automatic detection:

```lua
local Heatmap = Upview:GetService("Heatmap")

-- Manually set an anchor
Heatmap:SetPlayerAnchor(player, workspace.House.Floor, "My_House")

-- Clear anchor (reverts to world-space tracking)
Heatmap:SetPlayerAnchor(player, nil)
```

<Warning>
  When using manual anchoring, disable auto-anchoring to avoid conflicts:
  ```lua
  HeatmapAutoAnchorEnabled = false
  ```
</Warning>

## Data Schema

Each spatial data point includes:

| Field | Type | Description |
|-------|------|-------------|
| `x`, `y`, `z` | float | Position (world-space or object-space if anchored) |
| `player_id` | string | Roblox UserId |
| `session_id` | string | SDK session identifier |
| `anchor_context` | string? | Name of the active anchor (e.g., "Standard_House_Layout") |
| `zone` | string? | Name of the zone the player is in |
| `emotion` | string? | Current player emotion |
| `event_type` | string? | Event type for markers (death, purchase, etc.) |
| `event_data` | json? | Additional metadata for events |
| `created_at` | timestamp | When the point was recorded |

## API Reference

### GET `/api/workspaces/{workspaceId}/heatmaps`

Fetch spatial data with optional filters.

**Query Parameters:**

| Param | Type | Description |
|-------|------|-------------|
| `context` | string | Filter by anchor context |
| `zone` | string | Filter by zone name |
| `emotion` | string | Filter by emotion |
| `event` | string | Filter by event type |
| `player` | string | Filter by player ID |
| `from` | ISO datetime | Start of time range |
| `to` | ISO datetime | End of time range |
| `limit` | number | Max points to return (default: 5000, max: 10000) |

**Response:**

```json
{
  "points": [...],
  "sessions": [...],
  "overlays": [...],
  "filters": {
    "contexts": ["Standard_House_Layout"],
    "zones": ["Lobby", "BossRoom"],
    "emotions": ["happy", "frustrated"],
    "events": ["death"],
    "players": ["12345"]
  },
  "stats": {
    "totalPoints": 1234,
    "uniquePlayers": 8,
    "topEmotion": "happy",
    "topZone": "Lobby",
    "emotionBreakdown": { "happy": 400, "frustrated": 200 },
    "zoneBreakdown": { "Lobby": 600, "BossRoom": 300 },
    "timeRange": { "start": "...", "end": "..." }
  }
}
```

## Best Practices

<CardGroup cols={2}>
  <Card title="Use Object-Space Anchors" icon="anchor">
    Tag identical structures (houses, arenas) with the same `UpviewContext`. This merges their heatmaps, giving you statistically significant data even from small player samples.
  </Card>
  <Card title="Name Your Zones" icon="map">
    Clearly named zones make the analytics sidebar immediately useful. Use names like "Lobby", "BossRoom", "Shop" rather than "Zone1", "Zone2".
  </Card>
  <Card title="Wire Up Emotions" icon="face-smile">
    Even basic emotion tracking (death → frustrated, purchase → excited) dramatically increases the value of your heatmap data.
  </Card>
  <Card title="Record Critical Events" icon="flag">
    Use `RecordEvent()` for deaths, purchases, and key interactions. These appear as distinct markers on the map, pinpointing problem areas.
  </Card>
</CardGroup>
