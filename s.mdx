Custom events let you track anything that matters in your game. Level completions, boss kills, shop interactions, matchmaking results — any named event with optional metadata.

## `Upview:TrackEvent(eventType, data?, playerId?)`

Sends a named event to the Upview dashboard.

<ParamField path="eventType" type="string" required>
  The event name. Built-in types include `"player_joined"`, `"player_left"`, `"heartbeat"`, `"error"`, `"zone_entered"`, `"zone_exited"`. Any other string is treated as a custom event.
</ParamField>

<ParamField path="data" type="table?">
  Optional metadata. A flat key-value table. Values can be strings, numbers, or booleans.
</ParamField>

<ParamField path="playerId" type="string?">
  Optional player attribution. Pass `tostring(player.UserId)` to link the event to a specific player. If omitted, the event is server-level.
</ParamField>

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Upview = require(ReplicatedStorage.Upview)

Upview:Init({
    ApiKey = "uv_live_abc123...",
}):Start()
```

### Examples

<CodeGroup>
```lua Level Completion
Upview:TrackEvent("level_complete", {
    level = 5,
    completionTime = 120.5,
    starsEarned = 3,
    difficulty = "hard",
}, tostring(player.UserId))
```

```lua Purchase
Upview:TrackEvent("purchase", {
    itemId = "sword_001",
    itemName = "Flame Sword",
    price = 500,
    currency = "coins",
}, tostring(player.UserId))
```

```lua Match Result
Upview:TrackEvent("match_end", {
    winner = tostring(winnerPlayer.UserId),
    duration = 180,
    map = "desert_arena",
    playerCount = 8,
})
```

```lua Boss Kill
Upview:TrackEvent("boss_killed", {
    bossName = "Dragon King",
    attemptNumber = 3,
    partySize = 4,
    damageDealt = 15000,
}, tostring(player.UserId))
```
</CodeGroup>

## TelemetryService Custom Events

You can also track custom events through the TelemetryService directly. Events tracked this way are prefixed with `custom_` automatically.

### `TelemetryService:TrackCustomEvent(name, data?, playerId?)`

<ParamField path="name" type="string" required>
  The event name. The SDK prepends `"custom_"` to this value before sending.
</ParamField>

<ParamField path="data" type="table?">
  Optional metadata table.
</ParamField>

<ParamField path="playerId" type="string?">
  Optional player attribution.
</ParamField>

```lua
local TelemetryService = Upview:GetService("Telemetry")

TelemetryService:TrackCustomEvent("level_complete", {
    level = 5,
    time = 120.5,
    stars = 3,
}, tostring(player.UserId))
-- This is sent as event type "custom_level_complete"
```

<Note>
`Upview:TrackEvent()` sends events with the exact name you provide. `TelemetryService:TrackCustomEvent()` prepends `"custom_"` to the name. Use whichever convention you prefer, but be consistent — the dashboard groups events by name.
</Note>

## Event Naming

The dashboard groups events by their `eventType` string. Consistent naming matters.

**Do this:**
```lua
Upview:TrackEvent("level_complete", { level = 5 })
Upview:TrackEvent("level_complete", { level = 6 })
-- Both appear under "level_complete" in the dashboard
```

**Not this:**
```lua
Upview:TrackEvent("level_complete", { level = 5 })
Upview:TrackEvent("LevelComplete", { level = 6 })
-- These are treated as two different events
```

<Tip>
Use `snake_case` for event names. It's consistent with the built-in event types (`player_joined`, `zone_entered`, etc.) and avoids case-sensitivity issues.
</Tip>

## Client-Side Events

If the SDK is required on the client, `TrackEvent` sends events through a RemoteEvent to the server, which then queues them normally. The client never makes HTTP requests directly.

```lua
-- This works from a LocalScript
Upview:TrackEvent("button_clicked", {
    buttonName = "PlayAgain",
    screen = "game_over",
})
-- The event is proxied to the server via RemoteEvent
```

## What Gets Sent

Each event is wrapped in a `BatchEvent` structure:

| Field | Value |
|---|---| 
| `Id` | Auto-generated UUID |
| `Type` | Your event name |
| `Timestamp` | Unix timestamp in milliseconds |
| `SessionId` | Current server session ID |
| `PlayerId` | The player ID you passed (if any) |
| `ServerId` | Roblox `game.JobId` |
| `Data` | Your metadata table |
| `Priority` | `"Normal"` (default for custom events) |

Events are batched and sent in groups. They don't fire individual HTTP requests.

## Performance

Events are queued in memory and flushed in batches (default: every 30 seconds or when 50 events accumulate). Calling `TrackEvent` is fast — it just appends to a table.

<Warning>
Don't call `TrackEvent` every frame or on every `Heartbeat`. The queue will fill up and trigger constant flushes. Track meaningful game events, not continuous state.
</Warning>

## Built-in Event Types

The SDK automatically tracks these events. You don't need to fire them manually:

| Event Type | When Fired | Data |
|---|---|---|
| `player_joined` | Player connects | userId, username, accountAge |
| `player_left` | Player disconnects | userId, sessionDuration, lastPosition |
| `heartbeat` | Every 60 seconds | playerCount, uptime |
| `telemetry_metrics` | Every 30 seconds | fps, memoryUsage, instanceCount, platform |
| `error` | On Lua error | message, stackTrace, fingerprint, context |
| `zone_entered` | Player enters a zone | zone name |
| `zone_exited` | Player exits a zone | zone name |
| `spatial_points` | Position buffer flush | points array, count |
| `feedback_form_opened` | Form shown to player | formId, formSlug |
| `feedback_form_completed` | Form submitted | formId, formSlug, submissionId |
| `feedback_form_closed` | Form closed without submit | formId, formSlug, duration |
| `map_bounds_report` | Map bounds set | minX, minZ, maxX, maxZ |
