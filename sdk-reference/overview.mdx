The Upview SDK is a Luau ModuleScript that runs in your Roblox game server. It collects player analytics, spatial data, feedback, and error reports — then sends everything to your [Upview dashboard](https://dash.upview.dev).

## What the SDK Does

| Feature | Description | Service |
|---|---|---|
| **Session Tracking** | Player joins, leaves, duration, platform | Core (automatic) |
| **Custom Events** | Track any named game event with metadata | Core |
| **Performance Metrics** | FPS, memory, instance count, heartbeat time | TelemetryService |
| **Error Capture** | Unhandled errors with stack traces and context | TelemetryService |
| **Position Tracking** | Player positions sampled every 2 seconds | HeatmapService |
| **Zone Detection** | Enter/exit events for tagged areas | HeatmapService |
| **Emotion Tagging** | Tag position data with player state | HeatmapService |
| **Spatial Events** | Deaths, purchases, interactions at exact positions | HeatmapService |
| **Feedback Forms** | Dynamic in-game forms with live updates | FeedbackService |

## Architecture

The SDK is a singleton. You `require` it once, call `Init()` with your API key, and call `Start()`. From that point, data collection is automatic.

```lua
local Upview = require(ReplicatedStorage.Upview)
Upview:Init({ ApiKey = "uv_live_..." }):Start()
```

Under the hood, the SDK has three services:

- **TelemetryService** — performance metrics and error tracking
- **HeatmapService** — spatial position tracking, zones, emotions, and events
- **FeedbackService** — form rendering, submission, and live updates

All data flows through a **DataQueue** — a batching engine that queues events and sends them via HTTP in groups. This keeps network overhead low and avoids frame spikes.

## Folder Structure

```
Upview/
├── init.lua              -- Entry point
├── Core/
│   ├── Upview.lua        -- Main SDK controller (singleton)
│   └── DataQueue.lua     -- Batching and HTTP pipeline
├── Services/
│   ├── TelemetryService.lua
│   ├── HeatmapService.lua
│   └── FeedbackService.lua
├── Components/
│   └── UIBinder.lua      -- Feedback form UI renderer
└── Shared/
    ├── Types.lua          -- Type definitions
    ├── Signal.lua         -- Event system
    └── Utils.lua          -- Utility functions
```

## Accessing Services

After init, access services with `GetService`:

```lua
local TelemetryService = Upview:GetService("Telemetry")
local HeatmapService = Upview:GetService("Heatmap")
local FeedbackService = Upview:GetService("Feedback")
```

## Core Signals

| Signal | Parameters | Description |
|---|---|---|
| `OnReady` | — | SDK is initialised and running |
| `OnError` | `string` | An SDK-level error occurred |
| `OnPlayerJoined` | `PlayerContext` | Player joined and context is ready |
| `OnPlayerLeft` | `Player` | Player is leaving the game |

## SDK Status

The SDK tracks its state via `Upview.Status`:

| Status | Meaning |
|---|---|
| `"Uninitialized"` | Default state before `Init()` |
| `"Initializing"` | `Init()` is running |
| `"Ready"` | `Init()` completed, `Start()` can be called |
| `"Error"` | Init failed (e.g. missing API key) |
| `"Stopped"` | `Stop()` or `Destroy()` was called |
