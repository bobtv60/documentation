This page lists every configuration option you can pass to `Upview:Init()`. Options you don't specify use their default values.

## Full Configuration Example

```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Upview = require(ReplicatedStorage.Upview.init)

Upview:Init({
    -- Required
    ApiKey = "uv_live_abc123...",

    -- Batching
    FlushInterval = 30,                         -- Seconds between batch flushes
    MaxBatchSize = 50,                          -- Events per batch before auto-flush
    MaxRetries = 3,                             -- Retry attempts for failed requests
    RetryBaseDelay = 2,                         -- Base seconds for exponential backoff

    -- Feature Toggles
    EnableDebugLogs = false,                    -- Print SDK activity to Output
    EnableTelemetry = true,                     -- Collect FPS, memory, instance count
    EnableFeedback = true,                      -- Enable feedback form system
    EnableErrorTracking = true,                 -- Capture unhandled Lua errors
}):Start()
```

## Core Options

<ParamField path="ApiKey" type="string" required>
  Your Upview API key. Starts with `uv_live_` (production) or `uv_test_` (development). Get this from your [dashboard](https://dash.upview.dev).
</ParamField>

## Batching Options

The SDK queues events in memory and sends them in batches via HTTP. These options control batching behaviour.

<ParamField path="FlushInterval" type="number">
  Seconds between automatic batch flushes. The flush loop runs on this interval regardless of queue size.\
  **Default:** `30`
</ParamField>

<ParamField path="MaxBatchSize" type="number">
  Maximum events per batch. When the queue reaches this count, a flush is triggered immediately.\
  **Default:** `50`
</ParamField>

<ParamField path="MaxRetries" type="number">
  Number of retry attempts when an HTTP request fails. Uses exponential backoff with a 60-second cap.\
  **Default:** `3`
</ParamField>

<ParamField path="RetryBaseDelay" type="number">
  Base delay in seconds for the first retry. Doubles on each subsequent retry.\
  **Default:** `2`
</ParamField>

<Note>
  The internal queue also has a hard cap of 500 events. If the queue is full, the oldest event is dropped to make room. This prevents memory issues if the API is unreachable.
</Note>

## Feature Toggles

<ParamField path="EnableDebugLogs" type="boolean">
  When `true`, the SDK prints detailed log messages to the Output window. Useful for development and debugging. Turn off in production to reduce noise.\
  **Default:** `false`
</ParamField>

<ParamField path="EnableTelemetry" type="boolean">
  When `true`, the TelemetryService collects performance metrics (FPS, memory usage, instance count) every 30 seconds and sends them as `telemetry_metrics` events.\
  **Default:** `true`
</ParamField>

<ParamField path="EnableFeedback" type="boolean">
  When `true`, the FeedbackService is initialised. It sets up RemoteEvents for client-server form communication, starts schema polling, and enables live updates via MessagingService.\
  **Default:** `true`
</ParamField>

<ParamField path="EnableErrorTracking" type="boolean">
  When `true`, the TelemetryService hooks into `ScriptContext.Error` and `LogService.MessageOut` to capture unhandled Lua errors with stack traces and performance context.\
  **Default:** `true`
</ParamField>

## Internal Constants

These values are not configurable through `Init()` but are useful to know:

| Constant | Value | Description |
| --- | --- | --- |
| Max queue size | 500 | Hard limit on events in memory |
| Max bytes per batch | 500,000 | Size limit per HTTP request |
| Retry delay cap | 60 seconds | Maximum delay between retries |
| Metrics collection interval | 30 seconds | How often FPS/memory is sampled |
| Heartbeat interval | 60 seconds | How often server heartbeats are sent |
| Error rate limit | 10 per minute | Max automatic error captures per minute |
| Duplicate error cooldown | 60 seconds | Time before same error is captured again |
| Schema cache timeout | 600 seconds | How long form schemas stay cached |
| Schema polling interval | 300 seconds | How often the SDK checks for form updates |
